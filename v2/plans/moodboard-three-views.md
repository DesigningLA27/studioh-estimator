# V2.029 — one project moodboard, three views

Implemented the approved moodboard-options study as a presentation adapter over V1, not a second selection store.

- **01 Studio board:** project hero, category filters, grouped selection cards, palette and project/estimate sidebar.
- **02 Editorial:** image/story introduction, feature-first section arrangements and full-width palette/insight sections.
- **03 Visual wall:** deduplicated visual collection, category filters, palette/estimate sidebar and expandable original section tools.
- **Shared controls:** Add from library, native search, nine-step style/goals guide, category filters, section controls, hide/restore, palette groups, inspiration pins, insight customization, original suggestions and photo framing.
- **Presentation:** full-window view, visible Exit presentation, Escape exit; keeps selected layout.
- **Libraries:** Plant Book, material/furnishing records and color palettes offer Add/Use on Moodboard. Reuses native planting/specification actions; existing pricing/trade-line checks remain authoritative. Repeating Add retains an existing selection rather than toggling it off.
- **Data:** same S.moodboard, planting rows and specifications in every view; actual price-engine budget and totals. No new browser storage for layout, filter or presentation state. Cloud catalogs are read through the existing parent service boundary into memory; missing photos stay visible as placeholders.
- **Entry points:** Design → Open Moodboard and direct `?view=mood` open the actual board. The separate three-card illustrative board has been removed from this route.
- **V1:** root index.html is unchanged. Engine is regenerated by v2/build.py with the V2-only adapter. The catalog retry loop fix is needed for a usable board when V2 blocks original catalog reads.
